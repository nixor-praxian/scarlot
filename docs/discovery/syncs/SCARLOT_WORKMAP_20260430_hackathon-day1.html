David +A +P
Noon strategy reset with David Socratic, structural
framing resetDavid: "describe your company in three sentences as if I just walked in cold." The team's "the problem is safety" opener got rejected. Forced explicit articulation of customer / lifecycle / scope.
BREAKTHROUGH: layer not channelScarlot is not WhatsApp, it is a layer on top of channels. Discovery upstream out of scope. Meeting downstream out of scope. Messaging in between is the product.
BREAKTHROUGH: Mode C winsThree modes evaluated: A (Bailey's device-link), B (Scarlot-issued number per TDS), C (Scarlot as just another contact, TDS forwards). David pushed hard for C. Smallest data exposure, simplest LPD posture, lowest cognitive ramp.
tag-only, zero textReports are emoji + tag. No free text, no source attribution, no reveal mechanism. Defamation-safe and aligned with anonymity-first community norms.
V1 / V1.1 / V2 / V3 phasingV1 = reputation lookup chatbot. V1.1 = geographic gating + granularity. V2 = CRM (calendar / notes / contacts). V3 = communication assistance.
two POCs not oneReputation product and CRM product have different dynamics. Reputation = dirty data, clear willingness-to-pay, door opener. CRM = clean per-user, heavy engineering, upsell. Deploy separately.
user_id scope from day oneEvery entity scoped to user_id. Reputation DB is the only global store. Transport-agnostic abstraction so a future web app or other channel works without rewrite.
JID flips: limitation → featureThe unmappable WhatsApp ID is privacy-preserving by construction. Contact-card-share UX puts the user in control of what enters the safety database.
geographic gatingA Geneva TDS sees Geneva reports first. Both UX simplification and legal hedge. V1.1 mechanism (city / canton / radius) to be specified.
minimalist UX, separate training modeSteady state: forward contact, get emoji, done. No "how can I help you today". New users get a training-mode that teaches the patterns once.
Andrew pushback on Mode CStream access enables auto-detect, template learning, classifier training. David's response: don't assume those are valuable enough to justify the data exposure; let cohort tell us.
Philippe pushback on revealDavid's credit-bureau "request from reporter" pattern was rejected. Community anonymity is non-negotiable. Reconsider only if V1 traction requires it.
OpenClaude / NanoClaude distinctionThose platforms are general, auto-modifiable, single-user. Scarlot is stable, scoped, locked-down. Same primitives possible internally, but no skill self-installation by users.
vertical expansionSolo professional administrative reduction is the larger pattern. TDS is the entry point. Construction, viticulture, healthcare adjacencies.

David +A +P
David's harness architecture deep-dive technical reference
orchestrator + sandbox-per-queryRust orchestrator listens on channels. Per inbound, it composes a fresh sandbox: skills + system prompt + workspace + runtime. Agent killed after response. Strong isolation by construction.
BREAKTHROUGH: External Action patternAgent never holds API keys. Calls external_action(name, args). Orchestrator runs the credentialed script in a separate sandbox. Even an agent told to print every env var won't find the key.
Brain + subagents, cost-asymmetricBrain = Claude (heavy reasoning). Retriever / Transcriber / Scraper subagents = Gemini Flash. Subagents isolate context (Brain never sees the 25 wiki pages the Retriever read).
bubblewrap, ~30ms startupLinux namespace isolation. Faster than Docker (chosen for that reason). Inside Docker container of orchestrator. Production alternative: Firecracker for AWS-style serverless.
Nginx sidecar injects keysAgent sees localhost + placeholder key as env. Nginx intercepts and rewrites with real key. Credential rotation = sidecar config reload. Zero agent-side awareness.
Simplex as primary channelOutbound and inbound through different relays. Observer can't reconstruct conversation. Tor onion addresses available. Open source. Adapter is its own Docker container with WebSocket interface.
memory = wiki + skillsGit repo as wiki, read by Retriever subagent. Instructions skill for persistent rules. No separate memory subsystem; auditable, version-controlled, human-readable.
adopt the pattern, defer implementationConfirmed as Scarlot's reference architecture. V1 hackathon may start simpler (single agent, simple credential handling) but skills-as-directories and external_action are kept from day one because cheap-to-keep, expensive-to-retrofit.
"the innovation is not the tech"David: choosing Claude / Codex / Rig is a detail. The leverage is in skill definitions and interaction quality. Reinforces noon-david: build the UX, don't fall in love with the stack.
EU anti-scraping is weakDavid: "j'avais fait tout un dossier juridique là-dessus". Compilations of public reports get protection only with curation effort. Trojan Horse is on solid ground if we curate (cluster, tag, normalise).
reusable playbook producedSee docs/meta/harness-orchestrator-playbook.md. Project-agnostic spec for the same pattern, with checklist, threat model, sandbox primitive comparison, and skills/external_action templates.

Afternoon DevOps consultation with Daniel tactical, sharp
Tailscale for control plane ⟷ tenantNo public exposure of tenant API. Mesh networking via Tailscale. Tenant accepts only tailnet traffic. Self-signed TLS dropped (footgun risk).
rate limit everything from day onePer-IP rate limiting on every public endpoint. 429 on abuse. Most-skipped POC defence; cheapest to add; meaningful protection.
SQLite for V1, Postgres before V2Per-tenant SQLite is fine for hackathon and early beta. Multi-tenant cross-query workloads need Postgres. Migration scheduled, not "when there's time".
tenant network shapeTransient QR endpoint exposed only during Bailey's pairing. Steady state: zero inbound surface. Locked-down by default.
TLS dropped (POC)Self-signed TLS requires verify-bypass in code. Footgun: bypass gets copied somewhere it shouldn't. Drop for V1. If TLS required later, terminate in sidecar (Traefik / Caddy / init container), never in app.
