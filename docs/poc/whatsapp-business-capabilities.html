02 -- The three product surfaces

Three products,
three rule books.

Conflating these is the single most common error in product specs. The consumer app, the Business app, and the Business Platform are governed by different terms of service, surface different features, and have different programmatic access. The TDS already lives on surface 1. The question is what surface Scarlot lives on.

Surface 01
WhatsApp Messenger
The consumer app. Where every TDS in the cohort already operates. Free, encrypted, no programmatic seam.
  • Free peer-to-peer messenger
  • End-to-end encrypted by default (Signal protocol)
  • 1 primary phone + up to 4 linked devices
  • Multi-account on Android since 2024
  • No public API, everMeta has sued reverse-engineering vendors. Consistent posture for ten-plus years.
  • No programmatic access of any kind
  • No webhooks, no SDK, no bot platform
Surface 02
WhatsApp Business app
Free standalone Android/iOS app for small businesses and solo operators. Looks professional. No code required.
  • Free Android and iOS app for solo operators
  • Business profile (description, hours, address, category)
  • Catalog up to ~500 products
  • Quick replies (keyword snippets), labels, broadcast lists (256 max)
  • Automated greetings + away messagesTime-based only. No logic branching, no context awareness.
  • Click-to-chat links and downloadable QR codes
  • 1 phone + 4 linked devices (companion mode)
  • No API. No webhooks. No SDK.
  • Catalog cannot list adult products or servicesMeta Commerce Policy applies.
Surface 03
WhatsApp Business Platform
Meta's hosted API. Programmatic send and receive, paid per message, business verification required. The On-Premises variant sunset October 23, 2025.
  • Cloud API, Meta-hosted (On-Premises sunset Oct 23, 2025)
  • Programmatic send and receive via webhooks
  • Template messages, interactive buttons and lists, Flows
  • Voice calls via Calling API (launched July 2025)
  • 80 messages per second default, scales to 1,000 per second
  • Per-message pricing since July 1, 2025
  • Requires business verification + display name approval
  • Adult content prohibited by policyCascading bans, content scanning at the processing layer.
03 -- The customer service window

The 24-hour rule
governs everything.

On the Business Platform, there are two kinds of message: free-form (cheap, only allowed inside an open service window) and template (pre-approved, paid per delivery, allowed any time). The window opens when the user sends you a message and resets on each new inbound. Outside the window, you can only send pre-approved templates.

05 -- The hard limits

What WhatsApp
absolutely cannot do.

Common assumptions, debunked. If a vendor or framework claims any of these, they are reverse-engineering WhatsApp Web and the underlying account is one quality-rating drop from a permanent ban.

x
There is no API for personal WhatsApp accounts. Any vendor claiming this is reverse-engineering WhatsApp Web. Direct terms-of-service violation. Ban risk per number, escalating in 2025.
x
You cannot inject messages into existing personal chats via Cloud API. Cloud API messages come from the Cloud API number, not from the user's own number. There is no "send as another user" function.
x
Cloud API messages are not end-to-end encrypted. Meta decrypts at the processing layer to scan content for policy, fraud, and spam. Consumer-to-consumer chats are end-to-end. Cloud API chats are not.
x
One number equals one app. Personal Messenger, Business app, or Cloud API -- pick one. Coexistence (Business + Cloud API on the same number) was excluded for Switzerland at launch. Recheck before assuming.
x
The group chat API is not generally available. Native Cloud API group support exists since October 2025 but is gated to businesses with 100,000+ business-initiated conversations per month. Out of reach for any startup.
x
There is no background passive listening on a personal account. Even a paired companion device requires the user to have explicitly QR-paired and granted access through the official app.
x
Adult content and sex worker services are explicitly prohibited under WhatsApp Business policy. Detection runs on display name, profile description, catalog content, message content (Cloud API has plaintext access), recipient block-rate, and reply rate. The TDS's working identity cannot be the registered Cloud API business.
06 -- The July 1, 2025 pricing shift

From conversations
to per-message billing.

Meta switched its pricing model on July 1, 2025. Conversations are no longer the unit of billing for marketing, utility, and authentication templates. Each delivered template message now incurs a charge. Service messages inside an open 24-hour window remain free.

Before -- through June 30, 2025
Conversation-based pricing
A flat fee per 24-hour conversation window regardless of message count. Categories: Marketing, Utility, Authentication, Service. Service had a generous free tier of 1,000 conversations per month per business.
  • Charge fires once per opened window
  • Multi-message campaigns inside a window cost the same as single messages
  • Free service tier: 1,000 conversations / month
After -- from July 1, 2025
Per-message pricing
A charge fires on each delivered template message, not per conversation. Service messages and utility templates inside an open 24-hour window remain free. Free Entry Point (Click-to-WhatsApp Ads) window stays free for 72 hours.
  • Long campaigns now meaningfully more expensive
  • One-off outreach roughly the same cost
  • Service messages still free in 24h window
  • Free Entry Point window: 72h all free

07 -- The policy minefield

Why Cloud API does not
welcome the TDS identity.

The WhatsApp Business Messaging Policy applies to every Business Platform user. It references Meta's Commerce Policy and is enforced via machine-learning content scanning at the processing layer. These four clauses do the work of blocking the entire vertical:

Sexually explicit materials or nudity.WhatsApp Business Messaging Policy
Adult products and services.Meta Commerce Policy, referenced
Sexual performance enhancement products and sexually suggestive services.Meta Commerce Policy
Channels facilitating commercial sexual services.WhatsApp Channel Guidelines
Enforcement model
  • Machine-learning scans run on display name, profile description, catalog content, message content (Cloud API has plaintext access), recipient block-rate, and reply rate.
  • High recipient block-rate (typical for cold outreach in adult work) drives the negative-quality signal that triggers throttling.
  • Low reply rate (under ~10%) is itself a red flag, regardless of content.
  • Bans are account-level and cascade. Each violation tier escalates the next.
1 day › 3 day › 5 day › 7 day › Indefinite
Key insight
The only Cloud API path that survives policy review is one where the registered business is not the TDS. It is Scarlot itself, operating an internal-coverage agent the TDS chats with privately. The TDS's clients never touch the Cloud API number.

10 -- Key dates pin

The shape of the
last two years.

Material changes to the WhatsApp Business stack that affect the architectural call. Most are pricing or platform-level; a few are policy-level. Anchor each architectural decision to whichever of these is still in flight.

January 2024
On-Premises API v2.53 -- last feature release
Meta stopped shipping new features to the self-hosted API. Sunset clock starts.
Late 2023 / 2024
Multi-account on Android consumer WhatsApp
Two separate WhatsApp identities per phone, each on its own number. iOS still single-account.
2024
Coexistence launches (Business app + Cloud API)
First time the same number runs in two surfaces. Switzerland excluded at launch -- recheck before depending on it.
November 2024
Updated opt-in policy
Explicit consent before any business-initiated message. Demonstrable on demand. Bulk outbound without opt-in fast-tracks throttling.
2024 - 2025
Verified-business badge color: green to blue
Aligns with Facebook and Instagram. Same eligibility criteria (3-5 organic press articles or paid Meta Verified subscription).
July 1, 2025
Per-message pricing replaces conversation-based pricing
The most material billing change in the platform's history. Long campaigns become significantly more expensive. Service messages still free in the 24-hour window.
July 2025
Business Calling API launches (voice)
WebRTC-based, voice-only as of April 2026. DTMF / IVR navigation. Integrated into business thread context. Video promised, not shipped.
October 23, 2025
On-Premises API sunset complete
Self-hosted variant can no longer send messages. Cloud API is the only platform option from this date forward.
October 2025
Native Cloud API Group Chat (gated)
First-ever group support in the official platform. Limited to businesses with 100,000+ business-initiated conversations per month. Effectively unavailable to startups.
January 15, 2026
Brazil business payments program scaled back
WhatsApp Pay continues in India and Singapore for consumers; the Brazil business expansion is winding down. No path for CH or EU on the public roadmap.
