# State of the codebases — 2026-05-01

A single index pointing to the three component recaps generated on the day after Hackathon Day 1. Each document is authored from inside the repo it describes; this index keeps them findable from `scarlot-poc`.

| Component | What it is | Recap |
|---|---|---|
| Hernest / Scarlot | The TDS-facing assistant. WhatsApp-resident, admin-chat-only, semi-automatic. Owns clients, appointments, payments, blacklist, reminders. | `docs/poc/Project Recap - 2026-05-01.md` |
| Website | Public landing page and signup flow. Phone in, QR out. Bearer key held server-side. | `docs/poc/Website Overview - 2026-05-01.md` |
| Safety data | Reverse-lookup backbone. Aggregates community blacklists into a phone-keyed API. Phase 1 source: And6, fully ingested. | `docs/poc/Safety Data Recap - 2026-05-01.md` |

## How they fit together

```
Visitor
  │
  ▼
Website (scarlot-website)
  │   POST /api/contact   — phone in
  ▼
Hernest control plane (scarlot-admin)
  │   POST /v1/signup     — provisions a tenant container
  │   /qr/<token>         — WhatsApp pairing UI
  ▼
Per-tenant Scarlot container (one per TDS)
  │   admin chat in WhatsApp, 17 tools, SQLite
  │
  ╰── (planned) reverse-lookup call ─▶ Safety data API
```

Three properties are worth noting from the trio of recaps:

- **Public surface and tenant data are on different hosts.** A bug on the website cannot read tenant data. (`Project Recap` and `Website Overview` describe the host-www / host-a split.)
- **The safety data service does not know who is asking.** The agent calls the lookup with a phone number and gets a verdict; no tenant identifier crosses the boundary.
- **The safety bridge between Scarlot and the safety data service is not yet wired.** The plumbing exists in the agent (`apps/scarlot/src/safety/community-lookup.ts`) and the API contract is locked (`docs/poc/specs/safety-scraper/Trojan Horse - Shape expected.md`), but the multi-tenant API on the safety side (Phase 5) is not started.
